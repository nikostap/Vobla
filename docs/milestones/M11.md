# M11 — Административная платформа

## Что проверить

1. `/Admin` доступен административным ролям и показывает сводные метрики пользователей, объявлений, модерации, чатов, сделок, поисков и аудита.
2. Обычный пользователь получает отдельный `403 AccessDenied`, а не неясный редирект через вход.
3. Администратор видит пользователей, их роли и назначает дополнительную роль только с указанием причины.
4. Статус объявления меняется из административного реестра с обязательной причиной и записью истории.
5. Feature flags переключаются с причиной; Auditor имеет только чтение.
6. Задачи retention и saved-search matching запускаются из операционного центра, сохраняют статус и результат.
7. Аудит содержит актёра, роль, объект, старое/новое значение, причину, IP и correlation id.

## Автоматическая приёмка

- миграция `AdministrativePlatform` применена;
- создано 12 системных ролей, включая Owner, SeniorAdministrator, CatalogAdministrator, Auditor и профильные роли;
- Release build: 0 ошибок, 0 предупреждений;
- 26/26 Playwright UI-тестов, включая RBAC, feature flag, background job и аудит;
- `GET /health` = `200 Healthy`, Docker/PostgreSQL healthy.

## Ограничения

- demo-задачи запускаются в HTTP-запросе; постоянный worker/очередь можно вынести при hardening;
- финансовые модули и их разделение полномочий реализуются в M12;
- критические действия требуют причины, но повторная аутентификация/двухэтапное подтверждение остаются расширением.
