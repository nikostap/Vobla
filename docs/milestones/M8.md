# M8 — Чат

## Что проверить

1. Покупатель открывает активное объявление и нажимает «Написать продавцу»; повторное нажатие открывает тот же диалог.
2. Две независимые сессии видят online state и новые сообщения без reload; после reload история сохраняется, read receipt обновляется.
3. HTTP-форма остаётся fallback при недоступном WebSocket.
4. Внешняя ссылка блокируется; файл больше 20 МБ и неподдерживаемое расширение отклоняются.
5. Разрешённые JPG/PNG/WebP/PDF/TXT выдаются только авторизованному участнику через handler.
6. Жалоба и блокировка сохраняются; после блокировки composer недоступен обеим сторонам.
7. Продавец может сохранить быстрый ответ и включить автоответ для объявления.

## Автоматическая приёмка

- SignalR hub сохраняет сообщение в PostgreSQL до broadcast, reconnect не теряет историю;
- миграция `MessagingCore` применена;
- новый диалог создаётся только для `Active` объявления;
- Release build без ошибок/предупреждений;
- 23/23 Playwright UI-тестов, включая двухсессионный realtime, safety и reconnect;
- Docker/PostgreSQL healthy, health = 200.

## Ограничения

- antivirus представлен whitelist/quarantine boundary; production подключит отдельный scanner и object storage;
- расписание автоответов и reply-to UI оставлены для расширения;
- retention переписки должен быть утверждён юридически и вынесен в конфигурацию до production.
